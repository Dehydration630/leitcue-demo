# 一页案例：从生成一首音乐，到交付一集配乐

## 我的角色与项目阶段

独立产品发起人 / 产品负责人。承担问题定义、招募访谈、实验设计、音乐听评、规则设计、MVP 优先级、验收与上线组织；使用 AI 编程工具协助开发。当前为封闭 Alpha，不以独立项目包装团队规模或商业收入。

## 问题不是“有没有 AI 音乐模型”

创作者已经可以使用曲库或音乐生成工具。新的工具必须减少真实工作流中的试听、剪切和返工，不能只证明“某个模型能写出好听的歌”。交付物必须覆盖完整一集，还要保护原对白与叙事音效。

## 关键假设 → 实验 → 取舍

| 初始假设 | 观察与反例 | 产品取舍 |
|---|---|---|
| 卡点越多，视频越贴合 | 无意义强音破坏音乐；镜头变化不总是叙事重置 | 默认音乐连续，仅对持续关系/场景重置考虑换曲 |
| 一个强模型可以处理整集 | 长曲 intro 拖沓，氛围容易退化为独奏，边界有硬切 | 音乐功能路由 + 自动选段 + 独立装配 |
| 优质30秒就能推动采用 | 片段好评不解决后续完整作品的衔接 | 改为整集交付，采用/二次提交优于满意度 |
| 严格输出校验能提高可靠性 | 合理长句、重叠观察也会触发失败 | 保留原稿；有界规范化；观察可重叠，执行时间线不可重叠 |
| 限制最低15秒能避免碎片化 | 合理的6秒结尾重置被吞掉 | 最短5秒 + 数量上限 + 叙事重置证据，而非单一长度阈值 |
| 强调提示词就能消灭 intro | 模型仍按完整歌曲结构发展 | 把“成熟节奏入口”交给选段要求，不虚构精确作曲能力 |

## 已完成的交付

形成两条共用分析链路的交互：一键生成整集；或先查看剧情、选择音乐变化位置。生产系统包含异步任务、费用预留、模型适配、候选粗选、编排持久化、试听/导出和错误诊断。最近一轮界面迭代删去不必要的审批与解释，把视频和操作放到同一工作区。

## 怎么判断进展

功能测试通过证明系统能运行；负责人听评证明个别样本可用；真实创作者采用才证明任务价值。三者不能相互替代。目前没有足够数据报告稳定采用率、付费转化或留存。

## 下一轮最值得做什么

邀请少量创作者提交完整作品，保留原有配乐工作流作基线，记录总操作时间、修改次数、是否真实发布及是否二次提交。先验证任务价值，再投资更复杂的拍点/乐句识别与自动审美评分。
