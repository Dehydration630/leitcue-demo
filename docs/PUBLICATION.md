# 公开仓库边界与证据来源

## 三种不同的“完成”

1. **生产 Alpha 能力**：真实产品已实现的工作流；本公开版本概述其职责与边界。
2. **历史实验观察**：小样本、特定模型/输入/Adapter条件下的听评，不是普适结论。
3. **公开 Demo 与代码**：原创合成内容、为评审重写的简化实现；仅证明交互与规则可解释、可测试。

仓库不声称提供可直接运营的全栈源码，也不将模拟预算、示例时间轴或示例结果当作实测数据。

## 公开材料的组织依据

| 主题 | 私有项目证据类型 | 公开方式 |
|---|---|---|
| 问题与用户 | 初期访谈、后续真实任务反馈 | 去标识化的模式与研究偏差，不发布原话/录音 |
| 模型选择 | 冻结输入、盲评/解盲、失败记录 | 有边界的汇总表，不附第三方媒体 |
| 产品规则 | Hook/人声、密度、叙事连续、用户安排的迭代记录 | 更新后的PRD与决策，不复制过时状态 |
| 自动选段 | 结构代理算法说明、真实试听反馈 | 原理和限制；合成特征排序示例 |
| 工程交付 | 本地回归、隔离验收、运行版本与发布证据 | 描述已交付范围，不公开部署地址或回执 |

源代码示例为原创精简重写；静态Demo为专门制作的展示版，不是生产页面录屏。未复制原仓库Git历史、`.runtime`、环境配置、数据库、媒体、生产工作流或认证材料。

## 发布自检

- 文件清单白名单、禁用常见敏感文件后缀及目录。
- 扫描私钥、常见API token模式、邮箱、本机绝对路径、公网IPv4、签名URL和私有状态编号。
- 校验Markdown本地链接；运行Python和JS测试；人工检查网页桌面和移动端。
- 检查GitHub仓库确为独立demo，原生产仓库保持Private。

自动扫描只能降低风险，不能证明绝对无泄漏；因此从零构建公开目录，而不是把生产代码先复制再删密钥。
